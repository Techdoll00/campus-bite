# 饭点 FANDIAN · 校园食堂点评推荐

> 今天吃什么，别再纠结了。

一个决策优先的校园食堂工具：不是让你刷点评，而是在 10 秒内告诉你这顿吃哪个窗口、为什么，以及哪几道菜最近容易踩雷。

在线体验：https://techdoll00.github.io/campus-bite/

## 为什么不是「校园版大众点评」

大学生打开点评类产品的真实目的不是「逛」，而是「现在就要决定」。所以首页第一屏只做一件事：

- 根据**口味画像**（辣度 / 预算 / 忌口）、**当前餐段**、**实时排队**，直接给出一个推荐
- 推荐理由完全透明：为什么是它、为什么不是别的
- 一次不满意可以「换一个」，结果从候选池里重新挑

榜单和菜品库是支撑决策的证据，不是首页的主角。

## 核心功能

**1. 决策卡（首页）**
综合评分、预算、辣度、忌口、窗口排队时间打分；排除忌口菜品，过滤掉当前餐段不合适的甜品饮品；给出 2–3 条可解释的推荐理由。

**2. 踩雷预警**
只展示最近 7 天差评集中、且问题反复出现的菜。文案具体到「高峰期偏咸，肉丝也会变少」「等 20 分钟起，赶课别来」，而不是笼统的低分。

**3. 红榜 / 黑榜 / 新菜 / 省钱 / 早餐**
红榜按综合评分，黑榜按最近差评，新菜单独成榜。支持按食堂筛选。

**4. 食堂 · 窗口 · 菜品三层结构**
每个窗口显示当前排队人数与预估等待；菜品页有评分分布、真实点评、踩雷提醒和「怎么吃不踩雷」建议。

**5. 可用的点评闭环**
选星级、贴标签、写两句、匿名发布。点评写入 localStorage，刷新不丢；评分、点评数、我的点评列表会实时变化。

**6. 口味画像**
辣度、预算、忌口可视化调整，改完立即影响推荐结果。

## 设计取舍

- **视觉**：暖纸色 + 辣椒红 + 墨绿，票根式菜品卡与衬线数字，尽量避开「AI 生成的紫色渐变后台」观感。
- **移动优先**：底部 Tab、满宽决策卡、抽屉式点评；桌面端再展开为双栏编辑式布局。
- **数据**：虚构「青禾大学」3 个食堂、12 个窗口、49 道菜；排队人数按时间段模拟，点评由固定随机种子生成，避免每次刷新都变。
- **不做的**：登录、真实后端、图片上传。演示版本把精力放在产品结构和决策链路上。

## 技术栈

- React 19 + TypeScript + Vite
- 原生 CSS（设计变量 + 响应式），无 UI 框架
- Hash 路由，支持菜品深链
- localStorage 持久化偏好 / 收藏 / 点评 / 今日记录
- GitHub Actions 自动部署到 GitHub Pages

## 本地运行

```bash

npm run dev
```

构建：

```bash
npm run build
npm run preview
```

## 部署

推送到 `main` 后由 `.github/workflows/deploy.yml` 自动构建并发布到 GitHub Pages。`vite.config.ts` 中的 `base` 与仓库名保持一致。

### 链接稳定性约定

提交给面试官的链接固定为：

**https://techdoll00.github.io/campus-bite/**

后续迭代必须遵守以下约束，避免链接失效：

- 仓库名保持 `campus-bite`，不重命名、不转移、不删除
- 不添加 `CNAME` 或自定义域名，保持 GitHub Pages 默认域名
- `vite.config.ts` 的 `base` 保持 `/campus-bite/`
- 仓库保持 **Public**，Pages 的 Source 保持 **GitHub Actions**
- 所有更新直接 push 到 `main`，自动部署到同一域名

## 数据说明

食堂、窗口、菜品、点评均为演示数据，与任何真实学校无关。排队人数由时间段与固定随机种子模拟，不代表真实客流。
